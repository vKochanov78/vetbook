# VetBook — регистър на прегледите във ветеринарна амбулатория

Производствена практика, задание №2. Java 17+, Swing, SQLite, Maven.

**Отбор:** Валентин Кочанов · Васил Димитров · Стоян Динков

---

## Как се стартира

Нужна е само **Java 17 или по-нова**. Maven не се инсталира — проектът си го сваля сам.

```bash
git clone <адресът на хранилището>
cd vetbook

# Windows
mvnw.cmd clean package
java -jar target/vetbook.jar

# Linux / macOS
./mvnw clean package
java -jar target/vetbook.jar
```

Първото пускане тегли Maven (~9 MB) и зависимостите — трае минута-две. Следващите са мигновени.

Приложението само си създава базата `data/vetbook.db` и я пълни с примерни данни,
така че веднага има какво да се демонстрира. Ако искаш да започнеш на чисто —
изтрий папката `data/` и пусни отново.

Стартиране без пакетиране, докато се пише код:

```bash
mvnw.cmd exec:java
```

## Как е подреден проектът

Заданието (т. 6) иска слоевете да са разделени и в обработчиците на бутони да няма SQL.
Затова пакетите са пет и всеки има една-единствена работа:

| Пакет | За какво отговаря |
|---|---|
| `bg.vetbook.model` | Обикновени класове с данни — преглед, животно, собственик. Без логика. |
| `bg.vetbook.dao` | Единственото място със SQL. Връзка към базата и заявки. |
| `bg.vetbook.service` | Бизнес правилата от т. 5. Не знае нищо за прозорци. |
| `bg.vetbook.ui` | Swing екраните. Не знае нищо за SQL. |
| `bg.vetbook.config` | Настройките от `vetbook.properties`. |

Посоката е само надолу: `ui → service → dao → model`. Ако някога `dao` потрябва да
знае за `ui`, значи нещо е сложено на грешното място.

## Имена в базата

Уговорени в ден 1, за да не кръсти всеки таблиците по своему.
Таблиците са в множествено число, колоните с малки букви и долна черта.

| Таблица | Какво пази |
|---|---|
| `owners` | собственици: име, телефон, e-mail |
| `animals` | животни: вид, име, порода, година на раждане, собственик, златен картон |
| `doctors` | лекари |
| `visits` | прегледи: животно, лекар, дата и час, оплакване, диагноза, статус, такса |
| `visit_items` | процедури и медикаменти по преглед: количество и единична цена |

Статусите се пазят на английски (`SCHEDULED`, `IN_PROGRESS`, `COMPLETED`, `CANCELLED`)
и се превеждат чак в интерфейса. Така една правописна грешка в български текст не чупи заявка.

Пълната структура е в [`src/main/resources/db/schema.sql`](src/main/resources/db/schema.sql),
примерните данни — в [`seed.sql`](src/main/resources/db/seed.sql).

## Настройки

Всичко, което заданието иска да не е в кода, е в
[`src/main/resources/vetbook.properties`](src/main/resources/vetbook.properties):
такса за консултация, дневен лимит на лекар, продължителност на преглед, път до базата.

Ако сложиш файл `vetbook.properties` **до стартирания .jar**, стойностите в него
надделяват над вградените. Този файл не влиза в Git — всеки си има свой.

## Правила за работа с Git

1. **Настрой си името в Git.** Заданието иска историята да показва кой какво е правил:
   ```bash
   git config user.name "Твоето име"
   git config user.email "твоят@имейл"
   ```
2. `git pull` преди започване, `git push` при спиране. Не се трупа работа по три дни.
3. Един commit = едно завършено нещо, не целият ден накуп.
4. Папката `target/` и файлът на базата не влизат в Git — вече са в `.gitignore`.
